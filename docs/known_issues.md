# Known issues

Closed-issue log for CLI/GUI/runner issues found by read-only testing against
a real DB (`acta_cli/tmp/acta.db`, 2026-09-18), extended from 2026-09-19 with
items from a full static code review (rows 7–11, plus the GUI/CLI/runner DB
path mismatch in row 12). All items below are **fixed** and regression-pinned
in `acta_cli/tests`, `acta_db/tests` and `acta_runner/tests` — each row records
the fixing commit and the test(s) that pin the fix.

| # | Issue | Status | Repro |
|---|---|---|---|
| 1 | Trailing positional → rc 10 **but the payload is still emitted on stdout**: the handler runs and prints, then `commands_dispatch` rejects the leftover token. Stdout carries data while the exit code says failure (ambiguous T1 contract). | **fixed** (`ce14a22`): dispatch now rejects surplus positionals (tools-table count via `tool_entry_positionals`; `help` takes 1) BEFORE the handler runs — rc 10, stderr error line only, no stdout payload. Pinned by `test_trailing_help_rejected` (`stest_run_dispatch`) | `acta_cli context list 5` → rc 10, stdout empty |
| 2 | `model_revision get-latest` **ignores soft-delete** — returns the latest row by id even when `deleted_at` is set (latest *live* revision of model 1 in the test DB is id 2, get-latest returns deleted id 11). | **fixed** (`d678a12`): `acta_db_model_revision_get_latest` now filters `AND deleted_at IS NULL`. Pinned by `test_get_latest_multiple` (`acta_cli/tests/model_revision`) and `test_mr_get_latest_skips_deleted` (`acta_db/tests`) | `acta_cli model_revision get-latest 1` → expects live id 2 |
| 3 | `model_revision get <deleted>` returns rc 0 with the deleted row — inconsistent with `context get` / `exec get` (deleted → rc 1). | **fixed** (`4451244`): `acta_db_model_revision_get` now filters `AND deleted_at IS NULL`, so a deleted row is not-found → rc 1. Pinned by `test_get_deleted_revision` (`acta_cli/tests/model_revision`) and `test_mr_get_deleted` (`acta_db/tests`) | `acta_cli model_revision get 3` → rc 1, empty stdout |
| 4 | Revision listers include deleted rows **by default** and have no `--include_deleted` machinery (unlike context/exec/model/skill); `cli_spec.md` lists no flags for `model_revision count` yet `--include_deleted` is accepted as a no-op. Spec/code mismatch. Root cause of #2/#3: the revision queries in `acta_db` have no `deleted_at` filtering at all. | **fixed** (`c437b3e`): lister/counter default to live-only (`deleted_at IS NULL`); new `_with_deleted` DB variants + `--include_deleted` / `--deleted` flag on `model_revision list` (incl. `--count` short-circuit and `--stream`) and `count`, registered in the tools table; `cli_spec.md` rows updated. Pinned by `model_revision_test_deleted` (`acta_cli/tests/model_revision`) and `test_mr_list/count_excludes_deleted` + `*_with_deleted_includes_deleted` (`acta_db/tests`); stale deleted-row assertions in `test_integration.c` / `test_model.c` corrected | `acta_cli model_revision list 1` → 2 live rows; `--include_deleted` → 3 |
| 5 | `--verbose` help wording inconsistent: global says "repeatable, 1-3"; `db exec` help says "debug level 0-3" (implies a value). Doc-only. | **fixed** (`1e376a7`): global usage now reads `debug level 0-3 (repeatable, default 0)` and all per-entity help lines use `--verbose [N]` (optional, not implying a value) with the same `debug level 0-3` wording — one canonical phrasing everywhere | `db exec --help` vs `--help` |
| 6 | `log list` shows seed rows with `event: ""` (empty string, not NULL) — data quirk, not a CLI bug. Note `event` is `TEXT NOT NULL` in the schema, so NULL is not a valid fix. | **fixed**: seed row 1 of `acta_cli/acta_test_ref.sql` (and `acta_test_ref.db`) now carries `event='seed'` instead of `''`; comment in `execution_log_test_get.c` updated to match — data-only edit, no schema or test-shape change | `acta_cli --db acta_test_ref.db log list 1` |
| 7 | `acta_cli/src/main.c` includes `<io.h>` (Windows-only) for `dup` / `dup2` / `fileno` with no POSIX fallback (`<unistd.h>` / `<fcntl.h>`) — the `--out` fd-redirect does not compile on Linux/macOS, contradicting the README platform claim. | **fixed** (`c327a49`): `main.c` now selects the fd-redirect headers per platform — `#ifdef _WIN32` → `<io.h>`, else `<unistd.h>` (`dup` / `dup2` / `close`); `fileno` / `STDOUT_FILENO` already come from `<stdio.h>` on both, and `<fcntl.h>` is not needed (no `open()` / `O_*` usage in the file). Build-portability only — no runtime or test-shape change; verified compiling on a POSIX toolchain (2026-09-19) | `cc -c acta_cli/src/main.c` on a POSIX toolchain → compiles; previously `io.h: No such file or directory` |
| 8 | `acta_runner/src/backend.c`: `Authorization: Bearer %s` is `snprintf`'d into a fixed `char auth[512]` with no truncation check — a model-configuration `api_key` longer than ~500 chars is silently truncated (a wrong key is sent) instead of failing the execution. | **fixed** (`c64b74c`): the header is now built on a buffer sized for the key (`malloc(strlen(prefix) + strlen(api_key) + 1)`) — complete header for any key length, no truncation; `malloc` failure takes the existing `hdr_fail` → `BACKEND_ERR_ALLOC` path (runner: `FAIL(EXIT_HTTP, "backend transport failure: allocation failure")`). No `backend.h` contract change, no behaviour change for keys that fit; build + full test run verified (2026-09-19) | model `configuration` with `api_key` > 500 chars → full header sent; previously silently truncated |
| 9 | `acta_cli/src/argparse.c` `cmd_args_flag()` (space form) unconditionally returns `argv[i+1]` even when that token is another flag (e.g. `model list --name --table` → name = "--table"); a silently wrong value instead of a CLI usage error. The positional walker handles the same case correctly; only flag-value extraction is affected. | **fixed** (`cebd993`): `cmd_args_flag` now applies the positional walkers' tokenization — the space-form value is the next token only if it is not itself a flag — and `cmd_args_validate` rejects a value-taking flag with no non-flag value token (`--name --table` / `--name` as the last token) as a CLI usage error (exit 10, `missing value for --name`), mirroring pass 1's `missing value for --db` and the `cli_spec.md` exit-10 list. Pass-1 consumption untouched (pinned G3 `--json --table` → EXIT_INVALID via the handler's JSON parse). Pinned by G9 in `acta_cli/tests/gparse` | `acta_cli model list --name --table` → exit 10, `missing value for --name`; previously a silent filter by "--table" |
| 10 | `acta_runner/src/sweep.c` `last_activity()` reads the execution log list capped at `ACTA_DB_MAX_PAGE` (10,000) ordered `(created_at, id)` ASC; `rows[n-1]` is the newest *fetched* row, not the overall newest. An execution with > 10,000 log rows could be misjudged stale and swept. Theoretical at current pipeline size (a handful of rows per run). | **fixed** (`c3d37b8`): `last_activity()` now counts the total first (`acta_db_execution_log_count`) and fetches only the LAST page (`offset = total - limit`, `limit = min(total, ACTA_DB_MAX_PAGE)`), so `rows[n-1]` is the overall newest row for any row count; count failure falls back to the existing `started_at` / `created_at` chain. Pinned by scenario 11 in `acta_runner/tests/run/test_sweep.c` (a fresh row beyond the page cap is kept, not swept); build + full test run verified (2026-09-19) | n/a — pinned by the > 10,000-row scenario in the sweep suite |
| 11 | GUI: the "Show trash" checkbox state is persisted only for the skill and model panels; the context and execution panels have the same checkbox but its state is neither saved (`MainWindow::closeEvent`) nor restored (constructor) — it resets on every launch, inconsistent with the other two panels. | **fixed** (`494e988`): `MainWindow` now saves the context/execution checkbox states to QSettings (`window/showDeletedContext`, `window/showDeletedExecution`) in `closeEvent` and restores them in the constructor, mirroring the skill/model pattern — same no-op-on-unchanged `setChecked()` idiom; GUI build + full test run verified (2026-09-19) | launch GUI, tick "Show trash" in Executions, relaunch → stays checked |
| 12 | GUI/CLI/runner default DB path mismatch: the GUI wrote to the org-bearing `QStandardPaths::AppDataLocation` (`%APPDATA%\boucaron\ACTA Gamma\acta.db` / `~/.local/share/boucaron/ACTA_Gamma/acta.db`) while `acta_cli` / `acta_runner` defaulted to `./acta.db` — zero-config runs silently targeted two different databases, and the org name leaked into every path. | **fixed**: all three binaries now default to the same org-free app-data file (`%APPDATA%\ACTA_Gamma\acta.db` Windows, `~/.local/share/ACTA_Gamma/acta.db` POSIX), `./acta.db` last resort + legacy `./acta.db` hint when the default DB is missing; resolution implemented in `acta_dbpath.c` (duplicated in lockstep in `acta_cli/src` and `acta_runner/src`) and mirrored in `MainWindow::defaultDbPath`; pinned by the new `acta_cli/tests/dbpath` suite. The QSettings org name also changed (`boucaron` → `ACTA Gamma`), so previously remembered GUI settings (database path, window state) are read from the new QSettings location and reset once — the old file (`~/.config/boucaron/ACTA Gamma.conf`) / registry key (`HKCU\Software\boucaron\ACTA Gamma`) is superseded, not deleted | `acta_gui` first launch + `acta_cli model list` with no flags/env vars → same file |
